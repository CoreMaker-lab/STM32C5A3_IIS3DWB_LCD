# IIS3DWB PC CRC定位 R6（继续使用MCU R5）

## 中英文界面 / Chinese-English UI

- 上位机支持中文和 English 双语切换，窗口顶部可选择 `中文` 或 `English`。
- 默认启动语言为中文；切换语言不会影响串口连接、采样、CSV记录、校准或 MCU 指令。
- 仅修改 PC 上位机文件，MCU 固件、协议和采集逻辑不变。

本包只更新PC上位机，不需要重新编译或烧录MCU。保持R5固件、26.667kHz和6M串口，方便复现间歇性CRC错误。此版本用于抓取原因，并未声称已修复串口数据损坏。

## 运行与取证

1. 退出旧上位机，将本包完整解压到新目录。需要Python3.10+；执行`python -m pip install -r requirements.txt`后运行start.bat或`python app.py`。
2. 窗口标题应为CRC定位R6，MCU仍应显示IIS3DWB_PERF_R5。选择对应CH343串口，波特率与MCU一致（当前6M），开始采集。
3. 连接时自动在本目录的diagnostics子目录写入serial_diagnostics.jsonl，界面日志显示位置。重新连接追加session_start记录，不覆盖前一次会话。
4. CRC/不连续事件再次明显增加后，点击断开，发送整个diagnostics文件夹（可ZIP）。不要只发截图；原始帧证据在文件里。

## 记录内容

- 每次CRC错误的时间、完整候选帧十六进制字节、MCU序号/样本索引、收到的CRC与PC重新计算的CRC、上一有效帧头信息。
- 帧头格式错误与CRC不匹配分开记录；保留原来的总错误计数和重同步算法。
- wire_gap独立列出device_flag、rate_change、sequence_gap、sample_index_gap，可同一次出现多种原因。设备标记本身不自动等于采集故障，开始/停止/切换/Flash暂停也可能产生。
- 记录PC实际发出的指令、MCU的STREAM/FIFO/WORK/PERF/NVM及版本回复、显示队列溢出，以及约10秒一次的接收摘要。
- 无错误时不逐帧写盘，避免持续全量记录影响吞吐。日志采用2MiB轮转、最多当前+两份备份（约6MiB，单条超大记录可能略越界）。内存中解析错误证据队列最多64条；异常密集时仅保留最近64条，累计错误计数仍保留。
- 若程序目录无写权限，会提示诊断文件无法写入；请选择可写目录。此日志包含串口原始采样字节及设备运行信息，仅在本机保存。

未移除CRC检查，不伪造连续采样，不把缺失帧直接拼接用于FFT。原有CSV、校准、学习和模型界面保留，固定900px高度的界面间距略压缩。

## 当前证据的判断

用户新截图从CRC10/不连续10增长为CRC86/不连续66；同期MCU日志中gap=4、partial=19保持，fifo_ovr/read_err/drop/tx_drop/tx_err/uart_fault均为0。说明有新增接收完整性错误，不能当作启动计数；也不能仅凭板端错误为0就认定必然是USB线或PC。候选原因仍包括发送缓冲区/并发、UART链路/桥接驱动、接收解析等，需用原始帧进一步定位。

## 验证

PC共49项测试，48项通过、1项因缺少原MCU验证材料跳过。新增覆盖：字节翻转坏帧记录与后续好帧重同步、CRC重算一致、坏帧头与证据队列上限、文件轮转。原协议/CSV、各档采样率、校准、学习、UI及断点保护回归通过。Qt offscreen环境测试，不是Windows真实串口联调；尚未抓到用户现场的新错误帧。
